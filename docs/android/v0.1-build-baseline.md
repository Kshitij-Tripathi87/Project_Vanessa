# Vanessa Android v0.1 — build baseline

Day 1 of the v0.1 launch window is the reproducibility gate. This file records the exact
inputs used to produce an APK, so a later build can be compared against it instead of being
trusted on the strength of "it compiled".

Recorded 2026-11-13 on the reference development machine.

`minSdk` stays at 26 so the APK installs widely, but the native runtime targets API 28.
`LlamaCppInference.isAvailable` refuses to load the library below API 28, so API 26–27
devices stay in compatibility mode rather than failing at install time.

## Pinned native dependency

llama.cpp is not vendored. It is fetched at an exact revision:

- Repository: `https://github.com/ggml-org/llama.cpp.git`
- Commit: `67107ac34f62882d8b53ea41ad68010ea635b9be` (tag `b12164`)
- Location: `.toolchain/llama.cpp` (gitignored)

```sh
./scripts/fetch-llama-cpp.sh
cd apps/android
./gradlew :app:assembleDebug -PllamaCppDir="$(cd ../.. && pwd)/.toolchain/llama.cpp"
```

Without `-PllamaCppDir` the CMake external build is skipped entirely. That is deliberate —
CI and ordinary UI work should not need a native toolchain — but it means a plain
`assembleDebug` produces an APK with **no** inference runtime. That is exactly what happened
to the pre-existing artifact on this machine: the APK from 2026-11-13 20:45 was 41,807,782
bytes and contained only ML Kit barcode libraries. Any test against that APK could not have
exercised local inference.

`:app:verifyLocalInferenceApk` now fails the build when the runtime or an unexpectedly
embedded GGUF is missing from the APK.

python scripts/inspect_gguf.py pocket-copilot-voice/models/qwen3-0.6b/Qwen3-0.6B-Q8_0.gguf

This is the **base** Qwen3 0.6B model. It is not a fine-tuned Vanessa model, and no

the 40960 declared in the metadata, so prompt plus generation must fit in 2048 tokens.

## APK permissions (measured, not assumed)

The current manifest deliberately removes network access:

```
uses-permission: android.permission.READ_CALENDAR
uses-permission: com.vanessa.mobile.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

`INTERNET` and `ACCESS_NETWORK_STATE` are stripped with `tools:node="remove"`. This is a
correct default for the offline intelligence path and it means Day 6 cannot work until the
manifest is changed on purpose. It must never be "fixed" by weakening the offline path.

## Known deviations from the launch plan

- `GGML_OPENMP` is not forced `OFF` in `app/src/main/cpp/CMakeLists.txt`, so OpenMP is
  enabled and `libomp.so` ships inside the APK. It is self-contained, but it differs from the
  build flags written in the plan and costs a little APK size.
- Android CI (`/.github/workflows/android.yml`) runs `assembleDebug` **without** a llama.cpp
  checkout, so a green CI run proves the Kotlin app compiles, not that inference ships.
- No Release signing configuration exists yet; nothing has been signed or verified.
